# Plan feature

Do not edit files during this workflow unless the user explicitly asks.

1. Restate the user problem and intended outcome.
2. Identify confirmed requirements, assumptions, and unanswered questions.
3. Inspect relevant existing code and docs; cite exact paths and symbols.
4. Identify domain entities, state transitions, permissions, and invariants.
5. Map API, database, UI, background jobs, integrations, and observability impact.
6. Consider failure cases, concurrency, idempotency, privacy, and security.
7. Propose the smallest coherent implementation in ordered steps.
8. Define acceptance criteria and unit/integration/E2E tests.
9. List risks, migration/backward-compatibility concerns, and rollback approach.
10. Stop and ask for approval before implementation.
